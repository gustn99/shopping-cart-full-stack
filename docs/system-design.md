# 시퀀스 다이어그램

주요 사용자 시나리오를 바탕으로 시퀀스 다이어그램을 작성했습니다.

특히 에러 로직에서는 400 에러 등 코드 레벨의 에러는 생략하고, 품절이나 쿠폰 만료 등 유저 관점에서 피드백이 필요한 로직만 포함했습니다.

최종 검토하는 과정에서 발견된 추가 사항들은 박스로 표시되어 있습니다. 별도의 시나리오적 의미를 가지진 않으니 참고 부탁드립니다!

## 주문 확인 클릭

일반적인 커머스 서비스의 특성을 고려했을 때, 동시성 이슈가 제일 먼저 생각났습니다.

주문 단위로 상품에 대한 우선순위를 주기 위해 order를 만들었고, 해당 order가 만료되는 시나리오까지 생각해 보았습니다.

## 결제하기 버튼 클릭

구체적인 api 스펙은 결정하지 않았지만, 쿠폰 만료 피드백 등을 결제 api에서 처리하도록 계획했기 때문에 해당 시퀀스 다이어그램까지 그려보았습니다.

쿠폰 만료 플로우에서 만료는 두 가지 의미입니다.

- 단순 available 조건만 충족하지 않는 경우: order의 coupons에서 해당 id만 제거(UPDATE)합니다.
- 쿠폰의 만료일이 지난 경우: order의 coupons에서 해당 id를 제거(UPDATE)하고, 실제로 쿠폰을 삭제(DELETE)합니다.

다만, 반복 가능한 프로모션 쿠폰의 경우 삭제(DELETE)하는 대신 쿠폰 자체의 가시성 상태를 변경(UPDATE)하고 추후 만료일을 변경해 재사용하는 방식으로도 사용할 수 있을 것 같습니다.
